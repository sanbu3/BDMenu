## 本轮落地（2.4.0）

1. 显示真实界面与渲染尺寸，提供保持尺寸和 HiDPI 不变的 60 / 120 Hz 对照。
2. 所有模式切换先试用 15 秒，读回实际模式后显示确认。未确认自动恢复；退出恢复、启动恢复日志、显示器连接变化防误恢复。
3. 修复内建屏停用后 displayplacer 输出与 CGS 连接列表不同、导致模式切换验证被拒绝的问题。只允许缺省未启用屏幕，拒绝遗漏正在使用或已断开的目标。
4. 固定扩展栏且不自动隐藏时，停止鼠标轮询和 5 秒应用列表重建；通过 NSWorkspace 事件更新。需要指针感知时才轮询。相同应用状态不重复发布到 SwiftUI。
5. 保留旧目录未提交的 2.3.3 显示器开关与自动工作流修改及测试。没有重置用户偏好或辅助功能权限。

## 下一阶段优先级

- P1：把长模式列表拆为“界面尺寸 / HiDPI / 刷新率”，减少重复模式；模式 ID 必须在每次操作前重新核对，不能跨重连长期保存。
- P1：每台显示器保存办公、视频与高刷新配置；UUID 绑定，预览确认后才记忆。自动按应用切换需显式开启，避免前台应用变化造成频繁黑屏。
- P2：参考 MonitorControl 做可选亮度同步和 DDC 写入合并。以硬件背光优先，不能增加全屏遮罩或视频流来模拟普通亮度调节。
- P2：可导出的本机显示诊断报告，包含连接、模式、渲染尺寸、控制路径与短时采样。按需执行，不长期运行 powermetrics、不要求常驻 root 权限；未知值如实标为未知。
- P3：HDR、虚拟屏和窗口串流独立评估。存在额外渲染、带宽和采集权限成本，不能作为默认常驻路径。

## 性能验收

固定显示模式、相同外接屏与应用，分别记录 BDMenu 退出、启用但关闭控制中心、打开设置的 CPU、内存和能量表现。测量窗口切换、视频与鼠标跟随时要分开记录，避免将交互期采样当成待机。

显示配置 A/B 测试每次只改一个变量：先相同尺寸与 HiDPI 下比较 60 / 120 / 当前高刷新，再固定刷新率比较缩放。记录渲染尺寸、视频帧率、卡顿感受和 GPU 采样来源。单一 GPU busy 百分比不足以归因到某个进程，也不足以判断是否需要重装系统。

验收目标是减少无效唤醒和重绘；不承诺所有硬件条件下 GPU 为 0%，不把 60 Hz 当作万能修复。
