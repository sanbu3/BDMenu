# BDMenu 2.0 验证与迁移

## 自动验证

GitHub Actions 在 macOS 14 / Apple Silicon 上运行：

- Shell 语法检查及 4 项真实 CLI 入口测试：相对布局、旋转、缺失刷新率、参数边界和配置路径。
- `swift test`：编译整个应用，并测试 displayplacer 文本解析、独立模式编号、缺失刷新率、关闭屏幕记录、旋转、负坐标、切换主屏、镜像 UUID 组、连接集合验证和配置参数边界。
- 子进程测试：非零退出码、标准输出/错误、大量输出、超时强制结束、缺失工具、参数不经 Shell 执行。
- `./build.sh --adhoc`：从干净目录生成 ARM64 `.app`，逐个签名内置工具，再签名应用，执行 `codesign --verify --deep --strict`。
- 在内置工具上模拟下载/拷贝遗留的 resource fork，验证构建脚本只清理新生成的暂存应用包中的扩展属性，然后成功签名。
- 暂存与产物放在用户本地的 `~/Library/Application Support/BDMenu/Build`，避免放在可能由 iCloud 同步的桌面目录；安装脚本使用相同产物位置。

CI 使用临时签名，只验证打包流程；不代表验证了你的开发证书、辅助功能授权或真实显示器。

## 截图问题的处理

旧仓库的 `build.sh` 使用 `codesign -s -`。每次代码变化，临时签名的代码身份可能变化；截图中本地改用 Apple Development 后，旧授权也可能不再匹配当前应用。

1. 用固定身份执行 `./build.sh`，然后 `./install.sh`，固定从 `/Applications/BDMenu.app` 启动。
2. 在系统设置 → 隐私与安全性 → 辅助功能中，移除旧 BDMenu 条目。
3. 在应用中开启“亮度快捷键”，点击“打开辅助功能设置”，添加当前安装的应用并允许。
4. 应用约两秒内重新检查权限并启用监听。若系统仍报告旧状态，退出并重新打开当前安装的应用。
5. 以后更新继续使用相同 Bundle ID 和兼容的签名身份。签名类型、团队或授权记录变化时，仍可能需要重新授权；不能承诺“永久有效”。

应用不会修改 TCC 数据库，也不会全局重置其他应用的隐私权限。授权需要用户在系统设置中完成。

## Mac 上的人工验收

| 场景 | 预期 |
| --- | --- |
| 启动后始终不打开面板 | 自动工作流和已有授权的亮度键仍工作 |
| 面板关闭时授予/撤销辅助功能权限 | 约两秒内启用/停止监听，无重复授权弹窗 |
| 点击屏幕 A 的窗口，鼠标移到 B 后按 F4/F5 | 只调节 A，HUD 在 A；可切换为跟随鼠标 |
| 内建屏成为焦点后按 F4/F5 | 使用原生亮度控制，HUD 显示新值 |
| 录制按键、冲突按键、Esc 取消、关闭窗口、重启 | 正确保存绑定、拒绝冲突、录制期间不调整亮度，重启保留绑定 |
| 罗技 F4/F5 不发送标准 F 键 | 尝试录制实际媒体键，或设为标准 F 键／使用 Fn |
| 外置屏按亮度键、长按、⇧⌥精细调节 | 对应屏幕持续变化，HUD 显示正确，松开不产生额外系统调节 |
| 两块外置屏分别拖动亮度、音量 | 只修改对应 UUID 的显示器 |
| DDC 不支持 | 检测后显示“软件调光”；应用正常退出恢复先前色彩曲线 |
| 单次 DDC 写入失败 | 显示错误，不自动叠加软件调光 |
| DDC 支持的最大值不是 100 | UI 百分比转换为设备实际范围 |
| 开启自动工作流后拔出最后一块外置屏 | 内建屏恢复；无每秒无休止自刷新 |
| 睡眠/唤醒与外置屏重连 | 重新检测能力，恢复正确的独立控制状态 |
| 点击“全部点亮” | 恢复可识别实体屏和亮度，并暂停自动工作流 |
| 切换主屏 | 保留所有屏幕的相对坐标、旋转及启用状态 |
| 分辨率切换失败/显示器在过程中拔出 | 显示错误，不把界面标记成操作成功 |
| 镜像开关 | 一组镜像参数作为一个进程参数传递；关闭时恢复相同显示器组的原布局 |
| 退出应用 | 释放事件监听，恢复软件调光，以及自动工作流关闭的内建屏 |
| 登录启动需要审批 | 明确显示“需要允许”，可进入系统登录项设置 |

以上真实硬件场景需在用户的 Mac 和连接设备上验证。私有显示 API、显示器固件、线材、扩展坞、HDR/色彩管理都可能影响结果；应用中的错误状态不会把这些情况伪装成成功。

## 已知边界

- 开关显示器依赖 SkyLight 私有 API，系统更新后可能需要适配。
- 软件调光仅改变像素输出，不降低背光；最低保留 5% 曲线幅度，避免软件调成全黑。
- 输入源选项为常见 VCP 值，检测到可读输入源后才显示；具体接口支持取决于显示器。
- v1.2 用显示器 UUID 集合分别保存布局，不自动恢复旧版可能丢失旋转/关闭状态的 `savedLayout`。首次稳定连接后会重新记录。
- 外部硬件操作与完整 GUI 不在 CI 中模拟。通过构建和单元测试不等于完成实机验收。


## 1.4 密码入口辅助实机验收

- 内建屏在线时，身份验证继续使用原有方式；关闭功能后也不干预。
- 确认内建屏关闭、外接屏在线后，弹出具有“使用密码”的系统授权窗口，应切换为密码输入界面，最后的输入和提交仍由用户完成。
- 立即恢复内建屏或关闭开关，后台尚未执行的切换必须停止。
- 授予或撤销辅助功能权限，状态应相应变化；不应反复弹出授权请求。
- 普通应用、登录窗口、取消/允许/解锁等按钮均不由此功能点击。
- 受保护窗口或系统不开放 AXPress 时，保留手动密码入口；不得视为已完成切换。

自动测试仅覆盖窗口来源与按钮选择策略、停止/等待状态，不等于已在真实验证弹窗中验收。
